Git — система контроля версий

Git запоминает каждое изменение файлов. Как "сохранение игры" — в любой момент можно вернуться к любой точке истории.

Основные команды

BASH Добавить файл в список для сохранения 
git add README.md        # добавить конкретный файл
git add backend/         # добавить всю папку
git add .                # добавить все изменённые файлы
BASH Создать сохранение (коммит) 
git commit -m "описание изменений"
# -m означает message (сообщение)
# описание пишем кратко и по делу
BASH Отправить на GitHub 
git push                 # отправить текущую ветку
git push origin main     # явно указать: ветка main → сервер origin
BASH Проверить состояние и адреса 
git status               # что изменено, что добавлено
git remote -v            # показать адрес GitHub (origin)

Типичные ошибки

Authentication failed — ошибка авторизации
remote: No anonymous write access.
fatal: Authentication failed

Причина: токен не сохранён или устарел.

Решение
git config --global credential.helper store
GIT_TERMINAL_PROMPT=1 GIT_ASKPASS="" git push
# Ввести логин и токен — сохранится автоматически
refusing to allow — нет прав на workflow
refusing to allow a Personal Access Token to create or update workflow

Причина: токен не имеет права изменять GitHub Actions файлы.

Решение

Зайди на GitHub → Settings → Developer settings → Tokens. Добавь галочку workflow к токену.

Запомни: origin — это не коммит и не ветка. Это просто сохранённый адрес GitHub репозитория. Можно проверить: git remote -v

Docker — контейнеризация

Docker упаковывает приложение со всеми зависимостями в контейнер. Контейнер работает одинаково на любом компьютере — у тебя, у коллеги, на сервере.

Аналогия: Контейнер — как коробка с пиццей. Внутри всё что нужно: тесто, начинка, соус. Открыл коробку в любом месте — пицца одинаковая.

Dockerfile — инструкция сборки

DOCKERFILE backend/Dockerfile 
FROM python:3.12-slim
# FROM — взять готовый образ как основу
# python:3.12-slim — Python 3.12, slim = облегчённая версия

WORKDIR /app
# WORKDIR — все команды выполнять в /app внутри контейнера

COPY requirements.txt .
# COPY откуда куда
# . означает текущую папку = /app

RUN pip install -r requirements.txt
# RUN — выполнить команду во время сборки
# pip — менеджер пакетов Python

COPY . .
# копировать весь код — делаем после pip install
# чтобы при изменении кода не переустанавливать библиотеки

CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
# CMD — запустить при старте контейнера
# 0.0.0.0 — слушать все сетевые интерфейсы

Основные команды

BASH Управление контейнерами 
docker ps                    # запущенные контейнеры
docker ps -a                 # все включая остановленные
docker logs имя_контейнера   # логи контейнера
docker volume ls             # список volumes
docker volume prune          # удалить неиспользуемые volumes

Типичные ошибки

Permission denied — нет доступа к папке
ls: cannot open directory '/docker-entrypoint-initdb.d/': Permission denied

Причина: SELinux блокирует доступ контейнера к папке на хосте (Fedora).

Решение — добавить :z к volume
volumes:
  - ./db:/docker-entrypoint-initdb.d:z
# :z — метка для SELinux: разреши контейнеру читать папку
Port already in use — порт занят
failed to bind host port 0.0.0.0:3000/tcp: address already in use

Причина: другая программа уже использует этот порт.

Решение — найти и сменить порт
ss -tlnp | grep 3000    # найти что занимает порт

# изменить левый порт в docker-compose.yml
ports:
  - "3030:3000"   # Grafana теперь на localhost:3030
Запомни: image: берёт готовый образ с Docker Hub, build: собирает из Dockerfile. Используй image для стандартных сервисов (PostgreSQL, Redis), build — только для своего кода.

Docker Compose — управление стеком

Docker Compose позволяет запустить несколько контейнеров одной командой. Все настройки описаны в одном файле docker-compose.yml.

Аналогия: Если Docker — это один повар, то Docker Compose — это ресторан с несколькими поварами. Один файл описывает всю кухню: кто что делает, как связан с другими.

Структура файла

YAML docker-compose.yml 
services:              # список всех сервисов
  backend:             # название сервиса (придумываем сами)
    build: ./backend   # собрать из Dockerfile в папке backend/
    ports:
      - "8000:8000"    # левое:правое = хост:контейнер
    depends_on:
      - db             # запускать только после db и redis
      - redis

  db:
    image: postgres:16     # готовый образ с Docker Hub
    environment:           # переменные окружения
      POSTGRES_USER: devops
      POSTGRES_PASSWORD: devops
      POSTGRES_DB: portfolio
    ports:
      - "5432:5432"
    volumes:
      - ./db:/docker-entrypoint-initdb.d:z
      # ./db — папка на компьютере
      # /docker-entrypoint-initdb.d — папка в контейнере
      # :z — разрешение SELinux (нужно на Fedora)

  redis:
    image: redis:7
    ports:
      - "6379:6379"

  prometheus:
    image: prom/prometheus
    ports:
      - "9090:9090"

  grafana:
    image: grafana/grafana
    ports:
      - "3030:3000"   # 3000 был занят VS Code — поменяли на 3030

Основные команды

BASH Управление стеком 
docker compose up            # запустить все сервисы
docker compose up --build    # запустить с пересборкой образов
docker compose up -d         # запустить в фоне (терминал свободен)
docker compose down          # остановить и удалить контейнеры
docker compose down -v       # + удалить volumes (данные БД)
docker compose restart db    # перезапустить конкретный сервис

YAML — синтаксис

YAML — формат файла конфигурации. Главное правило — отступы строго через пробелы, не табы.

Неправильные отступы в YAML
services:
    backend:      # 4 пробела — ОШИБКА
      ports:
        - "8000:8000"

Причина: сервисы должны иметь 2 пробела, а не 4.

Правильные отступы
services:          # 0 пробелов
  backend:         # 2 пробела
    ports:         # 4 пробела
      - "8000:8000"  # 6 пробелов
Запомни: depends_on задаёт порядок запуска, но не ждёт пока сервис полностью готов. Если база стартует медленно — бэкенд может упасть и перезапуститься.
