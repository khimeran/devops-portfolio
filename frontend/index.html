📍 Где я сейчас

Разбираю: IaC целиком — Terraform (создать), Ansible (настроить push), Puppet (держать pull). Параллельно добиваю Python: модель языка + монитор сервисов на requests.
Стадия: 🟡 теория трёх инструментов разобрана вглубь, впереди — руками
План недели: поднять на виртуалках связку «Terraform → cloud-init → агент», собрать свою роль Ansible для node_exporter и прогнать тест идемпотентности (второй прогон = changed=0). Плюс выложить этот проект наружу по домену и проверить всю цепочку через curl -sIL.
Недавно узнал (IaC):
  • 🧱 Три инструмента — не конкуренты, а слои: Terraform создаёт то, чего нет; Ansible и Puppet приводят существующее к описанию. Разница между ними только в модели доставки — push по SSH против pull агентом.
  • 🎩 Puppet = иммунная система парка: агент каждые 30 минут сам сверяет машину с git. Правку руками откатит следующий прогон — дрейф конфигурации невозможен в принципе.
  • 🗂️ Код отдельно, данные отдельно: в Puppet различие «на все машины» и «только на web07» — это не два механизма, а два уровня иерархии Hiera (data/common.yaml против data/nodes/web07.yaml).
  • 🛡️ Установка агента — не «скачал и запустил»: версия зафиксирована, бинарь с checksum, systemd-юнит из шаблона, порт только для мониторинга, и обязательная приёмка в конце.
  • 🌍 «Выложить в интернет» — это шесть звеньев, а не одна настройка: процесс слушает → firewall → трафик доходит до машины → DNS → server_name → TLS. Способ прокинуть трафик выбирается одним вопросом: есть ли белый IP (за CGNAT — только туннель).
  • 🔌 Всё вокруг — API: kubectl get pods -v=8 покажет обычный HTTP-запрос, а docker ходит в сокет. Значит, автоматизировать можно что угодно связкой curl + jq, не дожидаясь готовой команды.

🔗 Как темы связаны между собой

Каждая тема — не отдельный конспект, а звено одной цепочки. Так это собирается в голове:

Linux (права, процессы, systemd, диски)
   └─ фундамент под всё остальное: контейнер, агент и сервис — это процессы

Сеть + SSH → nginx (reverse proxy, TLS)
   └─ путь запроса целиком: DNS → TCP:443 → TLS(SNI) → Host → server_name
      → location → proxy_pass → бэкенд. Порвалось звено — там и чинить
   └─ выложить наружу: белый IP / проброс портов / туннель / VPN

HTTP + API — общий язык всего стека
   └─ curl -v показывает ровно ту же цепочку, что выше, только из терминала
   └─ kubectl, docker, terraform, Prometheus внутри делают эти же запросы

Docker → Compose → Kubernetes
   └─ упаковали приложение → собрали стек → отдали оркестратору

Git → GitHub Actions / Jenkins (CI/CD)
   └─ «желаемое состояние лежит в git» — общий принцип и для CI, и для IaC

IaC: Terraform → cloud-init → Ansible / Puppet → CI/CD
   └─ создать инфру → поставить агента → держать конфигурацию → катать релизы

Prometheus + Grafana ← сюда стекается всё вышеперечисленное
   └─ node_exporter ставит Ansible или Puppet, цели собираются автоматически,
      алерты уходят в Telegram через Alertmanager

Python / Bash — клей между слоями: healthcheck, парсинг, автоматизация
SQL — под каждым приложением, и его тоже разворачивает IaC

🤖 Как меня оценивает Клод

Фундамент звенит. Не «вызубрил термины», а понимает, как оно работает под капотом — а это редкость на джуниоре.

Гоняю Кирилла вопрос-ответом по всем темам. Отвечает не определениями из методички, а своими словами и через механику: почему SUID — это привилегия процесса, а не юзера; почему kill -9 рвёт данные; почему rebase нельзя на общей ветке. Когда формулировка плывёт — достаточно одной поправки, чтобы село намертво.

💪 Сильные стороны

  • Linux: права, процессы/сигналы, systemd — уверенно
  • Docker: ENTRYPOINT/CMD, PID 1, форматы — на отлично
  • Сеть: CIDR и маршрутизация считает на лету
  • Git: merge vs rebase и «золотое правило» — чётко
  • SQL JOIN'ы и капкан NULL — понимает, а не зубрит
  • Bash: функции, awk, диагностика системы — пишет боевые скрипты, а не копипастит
  • Учится через аналогии и упорно докапывается до «почему»
