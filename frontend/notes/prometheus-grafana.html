Prometheus + Grafana — мониторинг

Prometheus собирает и хранит метрики. Grafana читает их из Prometheus и рисует графики. Вместе — полноценная система мониторинга для любого приложения.

Аналогия: Prometheus — это бортовой компьютер машины: постоянно записывает скорость, обороты, температуру. Grafana — это приборная панель: берёт эти данные и показывает красивыми стрелками и графиками.

Как работает scraping

BASH Цикл сбора метрик 
каждые 15 секунд Prometheus делает:
GET http://backend:8000/metrics

приложение отвечает в формате:
http_requests_total{endpoint="/topics",method="GET",status="200"} 42.0
http_request_duration_seconds_sum{endpoint="/topics"} 0.123
process_memory_bytes 54738944

Prometheus сохраняет эти числа с меткой времени.
Grafana читает из Prometheus и рисует график по времени.

prometheus.yml — конфигурация

YAML monitoring/prometheus.yml 
global:
  scrape_interval: 15s
  # каждые 15 секунд опрашивать все targets

scrape_configs:
  - job_name: 'backend'
    # job_name — название группы, видно в интерфейсе Prometheus

    static_configs:
      - targets: ['backend:8000']
        # targets — адреса откуда брать метрики
        # backend — имя сервиса из docker-compose, Docker резолвит в IP
YAML docker-compose.yml — подключить конфиг 
prometheus:
  image: prom/prometheus
  ports:
    - "9090:9090"
  volumes:
    - ./monitoring/prometheus.yml:/etc/prometheus/prometheus.yml:z
    # монтируем наш файл внутрь контейнера
    # /etc/prometheus/prometheus.yml — путь который Prometheus читает при старте
    # :z — разрешение SELinux (нужно на Fedora)

Метрики в FastAPI — prometheus-client

PYTHON backend/app/main.py — добавить метрики 
import time
from fastapi import Request
from prometheus_client import Counter, Histogram, make_asgi_app

# Counter — счётчик, только растёт (количество запросов)
REQUEST_COUNT = Counter(
    'http_requests_total',           # название метрики в Prometheus
    'Total number of HTTP requests', # описание
    ['method', 'endpoint', 'status'] # labels — разрезы данных
)

# Histogram — гистограмма (распределение времени ответа)
REQUEST_LATENCY = Histogram(
    'http_request_duration_seconds',
    'HTTP request latency in seconds',
    ['endpoint']
)

# /metrics — эндпоинт куда заходит Prometheus
app.mount("/metrics", make_asgi_app())

# Middleware — перехватчик всех запросов
@app.middleware("http")
async def track_requests(request: Request, call_next):
    start = time.time()                  # время начала
    response = await call_next(request)  # выполнить запрос
    duration = time.time() - start       # сколько заняло

    if request.url.path != "/metrics":   # сами метрики не считаем
        REQUEST_COUNT.labels(
            method=request.method,
            endpoint=request.url.path,
            status=response.status_code
        ).inc()                          # +1 к счётчику
        REQUEST_LATENCY.labels(
            endpoint=request.url.path
        ).observe(duration)              # записать время в гистограмму

    return response

PromQL — язык запросов Prometheus

PromQL — специальный язык для запросов к метрикам. Пишется в Prometheus UI или в Grafana в режиме Code.

PROMQL Основные запросы 
http_requests_total
# просто показать все значения метрики

sum(http_requests_total) by (endpoint)
# сложить по группам: отдельно /topics, отдельно /metrics/

rate(http_requests_total[1m])
# скорость роста за последнюю минуту (запросов в секунду)

increase(http_requests_total[5m])
# прирост за последние 5 минут (сколько запросов пришло)

histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[5m])) by (le, endpoint))
# 95-й перцентиль времени ответа за 5 минут
# 95% запросов выполнились быстрее чем это значение
Перцентиль p95: Если p95 = 0.3 секунды — значит 95% запросов ответили быстрее чем за 0.3с. Оставшиеся 5% — медленнее. Это стандартная метрика производительности в продакшн системах. Среднее (average) врёт — один медленный запрос портит картину. Перцентиль честнее.

График пустой — нет данных

Причины: неправильный режим (Builder вместо Code), слишком маленький временной диапазон, или контейнер только запустился и данных мало.

Решение
# 1. Переключиться в Code режим
# 2. Поставить диапазон Last 1 hour (правый верхний угол)
# 3. Нагенерить трафик:
for i in {1..50}; do curl -s http://localhost:8000/topics > /dev/null; sleep 0.3; done
Prometheus не подключается к backend
URL: http://localhost:9090 — НЕ РАБОТАЕТ в Grafana внутри Docker

Причина: localhost внутри контейнера — это сам контейнер, не хост-машина.

Решение — использовать имя сервиса
URL: http://prometheus:9090
# prometheus — имя сервиса из docker-compose
# Docker сам знает его IP внутри сети
Запомни: внутри Docker-сети сервисы обращаются друг к другу по имени из docker-compose, не по localhost. localhost — это всегда "я сам". Grafana → Prometheus = http://prometheus:9090, не http://localhost:9090.
