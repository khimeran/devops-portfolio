Jenkins — CI/CD сервер

Jenkins — сервер автоматизации. Он следит за репозиторием и при каждом изменении автоматически: собирает приложение, запускает тесты, деплоит на сервер. Это и называется CI/CD — непрерывная интеграция и доставка.

Аналогия: Jenkins — как конвейер на заводе. Ты положил деталь (сделал push в Git) — конвейер сам проверил, собрал, упаковал и отправил. Каждый шаг автоматический, ты только следишь за результатом.
Разница с GitHub Actions: GitHub Actions встроен в GitHub и бесплатен для открытых проектов. Jenkins — самостоятельный сервер, его нужно развернуть и поддерживать. Зато Jenkins более гибкий и популярен в корпоративной среде.

Установка через Docker

YAML docker-compose.yml — добавить Jenkins 
jenkins:
  image: jenkins/jenkins:lts
  # lts — Long Term Support, стабильная версия

  ports:
    - "8080:8080"    # веб-интерфейс
    - "50000:50000"  # подключение агентов Jenkins

  volumes:
    - jenkins_home:/var/jenkins_home
    # jenkins_home — постоянное хранилище данных Jenkins

volumes:
  jenkins_home:
BASH Получить первоначальный пароль 
docker exec jenkins cat /var/jenkins_home/secrets/initialAdminPassword
# Этот пароль вводится при первом входе на http://localhost:8080

Jenkinsfile — описание pipeline

Jenkinsfile хранится в корне репозитория. Jenkins читает его и знает что делать при каждом push.

GROOVY Jenkinsfile — декларативный pipeline 
pipeline {
    // pipeline — объявляем что это Jenkins pipeline

    agent any
    // agent any — запускать на любом доступном агенте (исполнителе)

    environment {
        IMAGE_NAME = 'my-app'
        // environment — переменные доступные во всех stages
    }

    stages {
        // stages — список этапов, выполняются по порядку

        stage('Checkout') {
            // stage — один этап с именем
            steps {
                checkout scm
                // checkout scm — скачать код из Git репозитория
            }
        }

        stage('Build') {
            steps {
                sh 'docker build -t ${IMAGE_NAME}:${BUILD_NUMBER} .'
                // sh — выполнить shell команду
                // BUILD_NUMBER — встроенная переменная Jenkins (номер сборки)
            }
        }

        stage('Test') {
            steps {
                sh 'docker run --rm ${IMAGE_NAME}:${BUILD_NUMBER} pytest'
                // pytest — запустить тесты внутри контейнера
            }
        }

        stage('Deploy') {
            when {
                branch 'main'
                // when — условие: этот этап только для ветки main
            }
            steps {
                sh 'docker compose up -d --build'
            }
        }
    }

    post {
        // post — что делать после всех stages

        success {
            echo 'Деплой прошёл успешно!'
        }
        failure {
            echo 'Что-то сломалось — проверь логи!'
            // здесь можно добавить уведомление в Slack
        }
        always {
            sh 'docker system prune -f'
            // always — выполнить в любом случае (чистка)
        }
    }
}

Ключевые понятия Jenkins

BASH Словарь Jenkins 
Job / Pipeline  — задача или набор задач для выполнения
Build           — один запуск pipeline (номер сборки)
Stage           — этап pipeline (Checkout, Build, Test, Deploy)
Step            — конкретное действие внутри stage
Agent / Node    — машина где выполняется pipeline
Artifact        — результат сборки (JAR, Docker image, .zip)
Workspace       — временная папка где лежит код во время сборки
Credential      — секрет (пароль, токен) хранящийся в Jenkins
Trigger         — условие запуска (push, schedule, другой job)

# Credentials — безопасное хранение секретов:
# Jenkins → Manage Jenkins → Credentials
# Добавить токен/пароль с ID → использовать в Jenkinsfile:
withCredentials([string(credentialsId: 'docker-token', variable: 'TOKEN')]) {
    sh 'docker login -u user -p ${TOKEN}'
}
Pipeline не запустился после push

Причина: Jenkins не знает о репозитории или не настроен webhook.

Решение — настроить webhook
# В GitHub репозитории:
# Settings → Webhooks → Add webhook
# Payload URL: http://jenkins-server:8080/github-webhook/
# Content type: application/json
# Events: Just the push event

# В Jenkins job:
# Configure → Build Triggers → GitHub hook trigger for GITScm polling
Запомни: Jenkinsfile нужно коммитить в репозиторий вместе с кодом. Это "pipeline as code" — конфигурация CI/CD хранится там же где код, версионируется и можно сделать code review изменений в pipeline.
