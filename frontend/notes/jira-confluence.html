Jira и Confluence

Jira — инструмент для управления задачами и проектами. Confluence — корпоративная wiki для документации. Оба продукта от Atlassian, тесно интегрированы друг с другом.

Аналогия: Jira — это список дел команды на доске (кто что делает, когда). Confluence — это папка с инструкциями, схемами и решениями (как это делать). Вместе: задача в Jira ссылается на инструкцию в Confluence.

Jira — управление задачами

BASH Словарь Jira 
Epic          — большая функциональность (3-6 месяцев работы)
               Пример: "Внедрить мониторинг"

Story         — пользовательская история (1-2 недели)
               Пример: "Как DevOps, я хочу видеть алерты в Slack"

Task          — конкретная техническая задача
               Пример: "Настроить alertmanager webhook для Slack"

Bug           — ошибка которую нужно исправить
Sub-task      — подзадача Story или Task

Sprint        — период работы, обычно 2 недели
               В начале спринта берём задачи в работу, в конце — review
Backlog       — список всех задач ещё не взятых в спринт
Board         — канбан-доска: To Do → In Progress → Done

Priority:
  Blocker     — всё стоит, чинить прямо сейчас
  Critical    — важно, сегодня
  Major       — следующий спринт
  Minor       — когда есть время
  Trivial     — косметика
BASH Workflow задачи в Jira 
To Do           — задача создана, никто не взял
In Progress     — кто-то работает прямо сейчас
In Review       — сделано, ждёт проверки (code review, тестирование)
Done            — готово и принято

# DevOps часто видит такие задачи:
#   "Настроить CI/CD для нового сервиса"
#   "Увеличить ресурсы БД на prod"
#   "Расследовать алерт: CPU > 90% ночью"
#   "Написать runbook для деплоя"

# Ключевые поля:
Assignee        — кто делает
Reporter        — кто создал
Labels          — теги (infrastructure, monitoring, urgent)
Components      — компонент системы (backend, database, network)
Fix Version     — к какому релизу должно быть готово

Confluence — база знаний команды

BASH Что хранят в Confluence DevOps команды 
Runbook         — пошаговая инструкция для конкретной операции
               "Как задеплоить на прод", "Как откатить релиз"
               "Что делать при алерте disk full"

Architecture    — схемы инфраструктуры, диаграммы
               Как устроена сеть, кластеры, связи между сервисами

Postmortem      — разбор инцидента после устранения
               Что случилось, почему, что сделали, что изменим

Onboarding      — инструкция для нового сотрудника
               Как получить доступы, настроить среду, что читать

Decision Log    — почему приняли то или иное техническое решение
               "Выбрали PostgreSQL вместо MySQL потому что..."

Changelog       — что изменилось в инфраструктуре и когда

Runbook — главный документ DevOps

BASH Пример структуры runbook 
# Runbook: Деплой на production

## Когда использовать
При выпуске новой версии приложения в prod.

## Предусловия
- [ ] Прошли все тесты в CI
- [ ] Есть бэкап базы данных
- [ ] Команда уведомлена

## Шаги

### 1. Подключиться к серверу
ssh deploy@prod-server-01

### 2. Обновить код
cd /app
git pull origin main

### 3. Запустить деплой
docker compose pull
docker compose up -d --no-deps backend

### 4. Проверить здоровье
curl http://localhost:8000/health
# Ожидаемый ответ: {"status": "healthy"}

### 5. Проверить логи
docker logs backend --tail=50

## Откат (если что-то пошло не так)
git checkout HEAD~1
docker compose up -d --no-deps backend

## Контакты при проблемах
On-call: @username в Slack канале #incidents

Интеграция Jira и Confluence

BASH Как связаны Jira и Confluence 
# В Jira задаче можно прикрепить страницу Confluence:
# → ссылка на runbook прямо из задачи
# → при инциденте открыл задачу и сразу видишь что делать

# В Confluence страница может показывать задачи из Jira:
# Макрос Jira Issues — вставляет живой список задач на страницу
# Postmortem в Confluence → ссылается на инцидент-задачу в Jira

# Git коммит → Jira:
# В сообщении коммита пиши номер задачи:
git commit -m "PROJ-123: настроить nginx для нового сервиса"
# GitHub/GitLab автоматически свяжет коммит с задачей PROJ-123

# Jira + GitHub Actions:
# После успешного деплоя автоматически закрывать задачу в Jira
# через Jira API или готовые actions
Практика: На собеседовании часто спрашивают как ты организуешь работу. Хороший ответ: "Задача создаётся в Jira с описанием и acceptance criteria. Во время работы пишу в комментарии что делаю. Runbook или изменения документирую в Confluence. В коммите ссылаюсь на номер задачи. После деплоя задача переходит в Done."
