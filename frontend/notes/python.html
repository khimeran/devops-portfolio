🐍 Python — язык и его законы

Учим Python с прицелом на парсинг, автоматизацию и API. Главное на старте — не зубрить библиотеки, а понять модель языка: на ней всё держится, и любая библиотека читается одинаково.

Перепрошивка мозга с Delphi/Pascal: Python динамический и интерпретируемый. Нет var-объявлений, нет типов у переменных, нет begin/end — блок задаётся отступом (4 пробела, не мешать с табами). Если «логика ломается» — почти всегда упёрся в Закон 2.

5 фундаментальных законов

Закон 1. ВСЁ — объект. Число, строка, список, функция, даже тип — всё объекты со своими методами. Поэтому точка . работает у всего: "привет".upper(), (5).bit_length(). Видишь что-то.что-то() — это «залезь в объект и вызови его метод».
Закон 2. Переменная — ЯРЛЫК, а не коробка 🏷️ (самый важный).
Delphi: x: Integer; x := 5 — коробка фиксированного типа. Python: x = 5 — стикер x наклеен на объект 5 в памяти. Переменная не хранит значение, а ссылается на него. Поэтому переклеить бирку на что угодно — норма.
PYTHONстикер можно переклеить
x = 5
x = "теперь строка"
x = [1, 2, 3]
# не ошибка! один стикер x тычет в разные объекты
Закон 3. Типов у переменных нет — типы у ЗНАЧЕНИЙ. Следствие Закона 2: тип живёт в объекте, не в стикере. Тип не объявляешь — Python смотрит на значение (динамическая типизация). Вот почему "5" + 3 падает: важны типы значений в момент операции, а не «что в переменной».
PYTHONтип идёт за значением
x = 5
type(x)        # <class 'int'>
x = "привет"
type(x)        # <class 'str'>  — тот же x, другой тип
Закон 4. Нет объявлений; присваивание создаёт имя; читать несозданное нельзя. Первое x = 5 одновременно создаёт стикер и вешает на значение. Читаешь имя, которого не присваивал → NameError (аналог set -u в bash).
Закон 5. Точка . = «залезь в объект». Библиотека — тоже объект с функциями 🔑.
import requests делает requests объектом-коробкой; requests.get() = «в коробке найди функцию get и вызови». Библиотеки не зубрят — берут 2-3 нужные функции и смотрят, что вернулось (а вернётся снова объект, в который снова тыкаешь точкой). Рекурсивно одинаково.
PYTHONтык точкой — везде один закон
import math
math.sqrt(16)     # в коробке math → функция sqrt
math.pi           # в коробке math → значение

import requests
r = requests.get("https://github.com")
r.status_code     # тык точкой в объект Response — ТА ЖЕ механика

Три фонарика: type / dir / help

Раз всё — объект, любой объект исследуется прямо в REPL, не зная библиотеки наизусть.

PYTHONкак ковырять незнакомое
type(x)          # ЧТО это? → класс/тип
dir(x)           # ЧТО умеет? → список всех методов и свойств
help(str.upper)  # КАК работает конкретный метод?
Изучать библиотеку без интернета: импортировал → dir() глянул методы → help() прочитал нужный. В dir() имена с __двойными__ подчёркиваниями (дандеры) — служебные; операторы это обёртки над ними: a + b зовёт a.__add__(b), len(x) зовёт x.__len__(). Поэтому "5"+"3"="53", а 5+3=8 — у str и int разный __add__.

Методы строк: встроенный инструментарий

То, за чем в bash бегал к внешним утилитам, у строки-объекта встроено методом:

PYTHONbash-утилита → метод строки
s = "  Привет, Мир  "
s.strip()                # tr -d ' ' / обрезать края
s.upper()                # tr a-z A-Z
s.replace("Мир", "Py")   # sed 's/Мир/Py/'
s.split(",")             # cut -d, / awk -F,  → возвращает СПИСОК
"мир" in s.lower()       # grep -q → True/False
Неизменяемость строк: s.upper() не меняет s, а возвращает новую строку. Хочешь сохранить — присвой: s = s.strip().

Цепочки методов = пайпы

Метод вернул объект → на нём сразу зовёшь следующий. Читается слева направо, как | в bash.

PYTHONцепочка и капкан типов
s.strip().upper().split()   # str → str → str → list (работает)

s.split().upper()           # split вернул LIST, у списка нет .upper()
# 💥 AttributeError: 'list' object has no attribute 'upper'
Капкан цепочки: работает, только если предыдущее звено вернуло объект, у которого есть следующий метод. Не уверен, что вернулось — проверь type(...). Прямой аналог пайпа: нельзя сунуть в команду то, что она не ест.

Аргументы: обязательные и со значением по умолчанию

PYTHONсигнатура: метод(обязат, необязат=дефолт)
help(str.split)   # split(sep=None, maxsplit=-1)
# = в сигнатуре = аргумент необязательный (есть дефолт)
# sep=None → дефолт = резать по пробелам

"a,b,c".split()       # ['a,b,c']       (нет пробелов — не порезал)
"a,b,c".split(",")    # ['a','b','c']   (режем по запятой)

requests.get(url, timeout=5)
# url — обязательный, timeout=5 — необязательный (переопределили дефолт)

Обработка ошибок: try / except

Ошибка времени выполнения = исключение. Не пойман — скрипт падает целиком. Пойман — продолжает жить.

PYTHONmonitor.py — мёртвый сайт не роняет скрипт
try:
    r = requests.get(url, timeout=5)   # пробуем
    code = r.status_code
    status = "OK" if r.ok else "FAIL"  # тернарный: знач_да if условие else знач_нет
except requests.exceptions.RequestException as e:
    code = "-"                          # сайт мёртв → аварийные значения
    status = "DOWN"                     # скрипт НЕ падает
print(url, "|", code, "|", status)
Как читать traceback: 90% портянки — кишки библиотек (site-packages/...), игнорь. Ищи свой файл и последнюю строку — там тип и суть ошибки. Ловят родителя RequestException — он покрывает потомков (ConnectionError, Timeout...). Наследование как в Delphi: поймал предка — поймал всех.
