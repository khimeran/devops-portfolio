🌬 Apache Airflow — оркестратор задач

Cron — будильник: «в 3:00 запусти скрипт». Он не знает, отработал ли скрипт, не умеет «сначала А, потом Б, а если А упало — Б не трогай», не хранит историю. Airflow — это cron, который вырос и стал прорабом: цепочки задач описываются кодом на Python, он запускает их по расписанию, следит за порядком, ретраит упавшее и рисует всё в веб-интерфейсе. Стандарт де-факто для пайплайнов данных.

DAG — главное слово Airflow

КОНЦЕПТ Directed Acyclic Graph — направленный ациклический граф 
DAG — цепочка задач со стрелками порядка:

  скачать_данные → обработать → загрузить_в_БД → дёрнуть_отчёт

направленный   — у стрелок есть направление (что за чем)
ациклический   — нельзя вернуться по кругу («обработай после загрузки,
                 а загрузи после обработки» = вечный день сурка, запрещено)

Задача (task) — один шаг графа. Оператор — ТИП шага:
  BashOperator   — выполнить shell-команду
  PythonOperator — вызвать python-функцию
  Sensor         — ЖДАТЬ события (появился файл, отработал другой DAG)

DAG описывается .py-файлом в папке dags/. Почему код, а не YAML/кнопки:
пайплайн можно генерить циклом, ветвить условиями, покрыть тестами
и хранить в git — конфиг на кнопках так не умеет.
PYTHON Минимальный DAG — файл dags/hello.py 
from airflow import DAG
from airflow.operators.bash import BashOperator
from datetime import datetime

with DAG(
    dag_id="hello",
    start_date=datetime(2026, 1, 1),
    schedule="0 3 * * *",          # знакомый cron-синтаксис
    catchup=False,                 # не догонять пропущенные запуски задним числом
) as dag:
    download = BashOperator(task_id="download", bash_command="curl -o /tmp/d.csv ...")
    process  = BashOperator(task_id="process",  bash_command="python process.py")

    download >> process            # стрелка порядка: сначала download, потом process

Архитектура: кто что делает

КОНЦЕПТ Компоненты и исполнители (executors) 
scheduler   ⭐ мозг: читает DAG-файлы, смотрит расписания, ставит задачи
            в очередь. Умер scheduler — ничего не запускается.
webserver   веб-морда (Flask): графы, история, логи, кнопка «перезапустить»
metadata DB память: состояния всех запусков. По умолчанию SQLite (игрушка),
            в проде — PostgreSQL
executor    КАК исполнять задачи:
  SequentialExecutor  по одной, только с SQLite. Для «попробовать»
  LocalExecutor       ⭐ параллельно процессами на той же машине + PostgreSQL.
                      Честный вариант для одного сервера
  CeleryExecutor      задачи уходят в очередь (Redis/RabbitMQ), их разбирают
                      WORKER-ы на других машинах. Горизонтальный масштаб
  KubernetesExecutor  под каждую задачу — под в k8s

git-sync    сайдкар, который периодически подтягивает папку dags/ из git-репо:
            деплой пайплайна = git push, никакого копирования руками
Мостик к остальным темам: в проде каждый компонент Airflow (scheduler, webserver, worker) — это отдельный systemd-сервис, метаданные — в PostgreSQL, даги приезжают через git, а веб-морду прикрывает nginx. Вся глава 1 стажировки собирается в одну картину именно здесь.
